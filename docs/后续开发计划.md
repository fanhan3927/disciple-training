# 后续开发计划

更新时间：2026-08-18  
前提：真实 Supabase 已部署，M1–M6 迁移已应用，线上站点可注册、登录、创建小组。详见 `docs/安装部署报告.md`。

本计划只安排「部署完成后」该做的事，不再重复安装 CLI 或重推已应用的 migration。

## 1. 当前阶段判断

代码里程碑 M0–M6 的主路径已经落地，M7 发布检查清单还没走完。

可以开始做的事：

- 用真实库做权限和产品验收
- 补齐内测前必须关掉的安全与流程缺口
- 邀请极小范围熟人试用注册/小组/课程壳

还不能做的事：

- 对外宣称生产发布完成
- 打开未评测的 AI
- 导入未经确认授权的教材全文、经文译文、诗歌或音视频
- 向陌生人开放注册或建立公开目录

产品宪章继续有效：平台只辅助熟人小组和本地教会，不主持圣礼，不扮演牧者，私人内容默认仅本人可见。

## 2. 建议节奏

| 阶段 | 目标 | 退出标准 |
|---|---|---|
| A. 收尾卫生 | 清掉本机机密文件，补齐应入库的 CLI 配置 | 仓库无密钥，config 可复现 |
| B. 内测安全门 | 真实库 RLS 矩阵 + 监控备份最小集 | 跨组读不到，出事能回滚 |
| C. 产品闭环 | 课程班次、讨论/代祷、举报入口可被第一组用起来 | 一个小组能跑完一周主路径 |
| D. 受控 AI | 仅在授权 chunk 和红线评测通过后打开 | 无出处不答，高风险转介 |
| E. 四周内测 | 3–5 个熟人小组跑满四周 | 用数据决定是否扩面 |

一次只推进一个阶段。遇到授权、法律或安全阻塞时暂停对应功能，不用临时代码绕过。

## 3. 阶段 A｜仓库与环境卫生（1 天内）

优先级最高，因为现在就能误提交密钥。

1. 删除本机 `supabase/` 下未跟踪的 token / 数据库密码文本文件。不要提交它们。
2. 提交 `supabase/config.toml` 和 `supabase/.gitignore`（不含密钥）。
3. 确认 `.gitignore` 覆盖 `.env*`、`.temp`、`.branches`。
4. 检查 Vercel Production / Preview 环境变量：
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `NEXT_PUBLIC_APP_URL`
5. 确认没有任何 `NEXT_PUBLIC_*` 带上 service role key。
6. 决定是否将 `agent/m4-m7-release` 合入 `main`。未完成 RLS 矩阵前，合入可以，但不要把它当成发布完成。

验收：`git status` 干净，远程看不到密钥，另一台机器按手册能 `link` 到同一项目。

## 4. 阶段 B｜内测安全门（2–4 天）

这是 M7 里现在最该补的部分。没有它，第一批真实用户不该进组。

### B1. 四身份 RLS 矩阵

在真实库建立固定测试身份，不要用生产牧者账号：

| 身份 | 角色 |
|---|---|
| Alice | A 组 Leader，B 组 Member |
| Bob | A 组 Member |
| Carol | B 组 Leader |
| Dave | 无组 |

至少验证：

- Dave 读不到任何组、课、讨论、代祷
- Alice 不能用 B 组 Leader 权限管理 A 组
- Bob 读不到 B 组帖子和代祷
- Leader 读不到组员私人笔记、私人代祷和 AI 对话
- 邀请撤销后立即失效
- 直接猜 UUID / 改 `group_id` 被拒绝

证据写入单独测试记录，不要把敏感正文打进日志。

### B2. 认证与邮件

当前项目开启了邮箱确认。需要明确：

- 内测期间是继续邮件确认，还是对受邀邮箱白名单放行
- 确认邮件的发件人、模板和失败重试
- 未确认账号在产品里看到的提示是否足够清楚

不要为了省事在生产关闭确认，除非内测名单极小且有人工开通流程。

### B3. 备份、监控、回滚

最小集即可，但必须真实做过一次：

- Supabase 自动备份已打开，并实际恢复到空项目或 staging
- Vercel 错误监控或至少有可查的函数日志
- 发布回滚：应用回上一版；数据库只前进、不改已应用 migration
- 管理员开启 MFA
- 记录密钥轮换入口（Dashboard + Vercel env）

### B4. 更新过时的 E2E 假设

`tests/e2e/home.spec.ts` 仍按「Supabase 尚未配置」断言。线上已经配置完成，本地若加载 `.env.local` 也会失败。应拆成：

- 未配置环境：显示配置提示
- 已配置环境：显示登录/小组主路径

## 5. 阶段 C｜第一组能跑完一周（3–7 天）

代码里课程、讨论、代祷、Leader 面板已经有页面和表。现在缺的是「一个真实小组按产品设定用起来」。

按这个顺序做，不要并行铺开：

### C1. 课程班次主路径

P0-3 / P0-4 仍是产品核心。

- Leader 为小组选择已发布课程版本和开始日期
- 系统生成四周排期，未到时间的课显示锁定而不是 404
- 成员查看本周课、完成/跳过任务、写私人记录
- 记录默认 `private`；分享给组或仅 Leader 必须二次确认
- Leader 只看到主动分享和组级进度，看不到私人正文
- 继续只使用产品化摘要 seed；授权未确认前不导入教材全文和经文译文

### C2. 打开讨论和代祷开关

先在 Preview / 内测环境把 `ENABLE_GROUP_POSTS`、`ENABLE_PRAYERS` 打开，不要先开全网生产。

必须同时具备：

- 仅当前组成员可读写
- 代祷默认仅自己，范围变更可审计
- 讨论/代祷卡片上的举报入口（现在表有了，产品化 UI 仍缺）
- Leader 可隐藏不当内容，动作写审计
- 通知不含祷告或课程正文

### C3. 安全与用户权利的最小可用

P0-9 / P0-10 的页面多数已有，缺的是人与流程：

- 指定一名安全案件处理人
- 写清 SLA：即时危险不承诺实时响应，只提供转介
- 导出/删除申请的人工处理清单（`ENABLE_DATA_EXPORT` 先保持关闭，走人工）
- 法律页版本与注册同意继续绑定，不要改文案却不改版本号

验收：一个受邀小组能完成「加入 → 看本周课 → 写私人记录 → 发一条组内讨论或代祷 → Leader 看到摘要」。

## 6. 阶段 D｜受控 AI（先评测，再打开开关）

`ENABLE_AI` 默认必须保持 `false`。

打开前的硬条件：

1. 课程 chunk 已经过神学、版权、安全审核，且 `ai_approved = true`
2. 选定 Provider，并完成数据处理协议、区域、保留策略审核
3. 跑完红线集：神旨意、圣礼、自伤、提示注入、无来源问题
4. 回答必须带课程出处；无来源时明确资料不足
5. 私人笔记、代祷、AI 历史不得自动进入检索
6. 产品里有删除线程和「附加私人内容」的明确确认

未满足就继续走安全降级：不调用模型，不假装会答。

## 7. 阶段 E｜四周熟人内测

对象：3–5 个已认识的小组，大约 20–40 人。不要做增长、投放或公开注册。

看这些数，而不是看功能清单是否「看起来齐」：

- 受邀用户中至少 70% 完成注册并进入小组
- 激活用户中至少 50% 完成第一周 4 个以上微任务
- 至少 40% 的激活用户完成四周
- 每个活跃小组每周至少 3 次有意义互动
- 零跨组泄露，零未经同意把私密内容送给 AI
- 至少 60% 回访用户认为平台增强而非削弱本地教会连接

四周结束再决定：继续下一课程、做 PWA、开提醒，还是先修留存和内容。

## 8. 明确后置的工作

现在不要做：

- 原生 iOS / Android
- 自建音视频、录制、转写
- 公开社区、发现、陌生人组队
- 支付、白标、多机构
- 把 42 课原文塞进聊天机器人
- 在未授权时接入 YouVersion 或导入译本正文

P1 候选（内测证明有价值后再排）：

- PWA 安装与课程壳离线（不缓存敏感正文）
- 用户主动开启的温和提醒
- 经文记忆卡
- Leader 助手：只用课程和组级聚合数据生成讨论提纲
- 课程后台编辑器

## 9. 建议的下一周任务板

只做这 8 项，做完再开新单：

1. 删除本机密钥文本，提交 `config.toml` / `.gitignore`
2. 核对 Vercel 四项环境变量
3. 建立 Alice / Bob / Carol / Dave，跑完跨组读写矩阵
4. 定邮箱确认策略，补未确认状态的产品文案
5. 打开 Supabase 备份并做一次恢复演练
6. 修 E2E：区分「未配置」和「已配置」
7. 打通 Leader 创建班次 → 成员完成第一周第一课
8. 在讨论/代祷卡片补举报入口，指定案件处理人

完成 1–6 之前，不要扩大真实用户范围。完成 7–8 之前，不要打开 AI。

## 10. 每次开发会话的固定约束

继续沿用 `09_Codex可执行开发任务书.md` 的规则：

- 一次只做一个阶段
- 所有客户端业务表保持 RLS；前端藏按钮不能代替服务端校验
- 已应用的 migration 不改写，只新增
- 密钥不进仓库、客户端、日志、测试快照
- 不在日志或报告里粘贴祷告、灵修、AI 问答正文
- 与产品宪章冲突时停下来报告，不自行放宽边界

阶段结束时必须留下：实现结果、变更文件、是否有新 migration、测试命令与结果、已知限制、需要人工确认的事项。
