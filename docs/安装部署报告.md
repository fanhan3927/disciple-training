## 2. 本轮完成了什么

### 2.1 本机环境

1. 确认 `npx supabase` 在当前 Windows + Node 环境下不可用（找不到 `win32-x64` 二进制包）。
2. 按《Supabase数据库迁移傻瓜式操作手册》下载官方 Windows amd64 ZIP，安装到 `C:\Tools\supabase`。
3. 将 `C:\Tools\supabase` 加入用户 PATH。新开 PowerShell 后可直接使用 `supabase`。
4. 在项目根目录执行 `supabase init`，生成 `supabase/config.toml` 和 `supabase/.gitignore`。

### 2.2 项目绑定

1. CLI 已登录，`supabase projects list` 可见项目。
2. 已执行 `supabase link --project-ref fqekgkpkivycbvmsmcel`。
3. 本地 `.env.local` 已配置 Project URL、publishable key 和服务端 secret key（新版 key 格式）。
4. 线上 Vercel 已配置公开 Supabase 变量；注册页不再显示「Supabase 尚未配置」。

## 5. 安全与卫生事项

1. 不要把 Access Token、数据库密码、anon key、service role key 写入聊天、文档或 Git。
2. 本机 `supabase/` 下曾出现未跟踪的本地机密文件（名称像 CLI token 和数据库密码）。不要提交；用完后删除。
3. `supabase/config.toml` 和 `supabase/.gitignore` 目前仍是未跟踪文件，可以提交；其中不含密钥。
4. `SUPABASE_SERVICE_ROLE_KEY` 只能放服务端环境变量，不能放进 `NEXT_PUBLIC_*`。
5. 生产环境只使用 `supabase db push`。不要对生产库执行 `supabase db reset`。
6. 已经成功执行过的 migration 文件不要改写。本次 M3 是在首次失败、远端未记录的情况下原地修复，因此允许；以后的改动一律新增更大编号的 migration。
